# Встановлення крок за кроком

Як поставити вузол Nevod на орендований сервер з нуля: від купівлі сервера до першого входу в панель адміністратора. Приклад — сервер з Ubuntu 24.04 і домен `node.example.org`; замість нього всюди підставляйте свій.

Усі команди нижче вводяться в терміналі сервера, їх можна копіювати цілком. Що таке вузол і що він зберігає — у розділі [Як влаштований вузол](../node-how/).

## 1. Орендуйте сервер

Підійде будь-який VPS у будь-якого провайдера: 1 процесор, 1 ГБ пам'яті, 10 ГБ диска, система **Ubuntu 24.04**. Під час замовлення провайдер видасть **IP-адресу** сервера й пароль користувача `root` (або попросить завантажити SSH-ключ).

Якщо в провайдера є свій мережевий файрвол у панелі керування (наприклад, Firewalls у Hetzner, Security groups в інших), відкрийте в ньому вхідні порти **22, 80, 443 і 8765** (TCP).

## 2. Спрямуйте домен на сервер

Вузлу потрібен власний домен або піддомен, наприклад `node.example.org`. Без нього не обійтися з двох причин:

- **Телефони підключаються до вузла за адресою `https://домен/nevod-ws`.** Сертифікат HTTPS, якому iPhone довіряє без жодних налаштувань, Caddy отримує від Let's Encrypt на доменне ім'я.
- **Адреса вузла зберігається в усіх:** у телефонах користувачів, у їхніх контактних картках, в інших вузлах мережі. Якщо ви переїдете на інший сервер або провайдер змінить IP-адресу, досить виправити один DNS-запис — користувачі нічого не помітять. З голою IP-адресою після переїзду зв'язок зник би в усіх, і запрошення довелося б розсилати знову.

Якщо власного домену ще немає, його можна купити в будь-якого реєстратора (Cloudflare, Namecheap, Porkbun, Gandi та інші) — зазвичай це кілька доларів або євро на рік. Для вузла достатньо одного піддомену, а сам домен можна використовувати і для чогось іншого.

У панелі керування вашим доменом створіть **A-запис**: ім'я — наприклад `node` (вийде `node.example.org`), значення — IP-адреса сервера.

Зачекайте кілька хвилин і перевірте з будь-якого комп'ютера:

```
ping node.example.org
```

У відповіді має бути IP-адреса вашого сервера. Поки цього немає, далі йти безглуздо: сертифікат HTTPS видається лише домену, який уже вказує на сервер.

> Якщо домен обслуговує Cloudflare, вимкніть для цього запису проксіювання (сіра хмаринка, «DNS only»). Інакше телефони й інші вузли підключатимуться до Cloudflare, а не до вашого сервера.

## 3. Підключіться до сервера

На своєму комп'ютері відкрийте термінал (на Windows — PowerShell, на Mac — «Термінал») і введіть:

```
ssh root@node.example.org
```

Під час першого підключення відповідайте `yes` і введіть пароль від провайдера.

## 4. Встановіть Docker і git

```
apt update && apt upgrade -y
apt install -y git
curl -fsSL https://get.docker.com | sh
```

Остання команда — офіційний інсталятор Docker. Перевірте, що все на місці:

```
docker compose version
```

Має з'явитися рядок вигляду `Docker Compose version v2…`.

## 5. Увімкніть файрвол

```
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8765/tcp
ufw enable
```

На питання відповідайте `y`. Порти 80 і 443 потрібні для HTTPS (телефони й панель), 8765 — для зв'язку з іншими вузлами.

> Docker відкриває порти своїх контейнерів сам, в обхід `ufw`. Тому в нашому комплекті панель адміністратора (порт 8766) опублікована лише для самого сервера — не змінюйте це в `docker-compose.yml`.

## 6. Завантажте Nevod

```
git clone https://github.com/avk0978/nevod-messenger.git /opt/nevod
cd /opt/nevod/installer/docker
```

## 7. Заповніть налаштування

Створіть файл налаштувань зі зразка:

```
cp .env.example .env
```

Придумайте пароль для панелі адміністратора. Найзручніше згенерувати довгий випадковий:

```
openssl rand -base64 24
```

Скопіюйте результат і збережіть його в менеджері паролів. Тепер відкрийте файл налаштувань:

```
nano .env
```

Змініть два рядки:

```
NEVOD_DOMAIN=node.example.org
NEVOD_ADMIN_PASSWORD=сюди-згенерований-пароль
```

Решту залиште як є. Збережіть файл: **Ctrl+O**, потім **Enter**, вихід — **Ctrl+X**.

| Налаштування | Що означає |
|---|---|
| `NEVOD_DOMAIN` | Домен вузла. Телефони підключаються до `https://домен/nevod-ws`, інші вузли — до `домен:8765`. |
| `NEVOD_ADMIN_PASSWORD` | Пароль панелі адміністратора. Без нього вузол не запуститься. |
| `NEVOD_ADMIN_PUBLIC` | `true` — панель відкривається в браузері за адресою `https://домен/nevod-admin`; `false` — панель закрита для інтернету (див. крок 10). |
| `TURN_SECRET` | Лише якщо ви ставите свій ретранслятор дзвінків, див. [Дзвінки через власний вузол](../node-turn/). Зазвичай порожньо. |

## 8. Запустіть вузол

```
docker compose up -d --build
```

Перший запуск займає кілька хвилин: Docker збирає образ вузла й завантажує Caddy. Коли команда закінчиться, перевірте:

```
docker compose ps
```

Обидва контейнери — `nevod_node` і `nevod_caddy` — мають бути в стані `Up` (або `running`).

## 9. Перевірте, що все працює

Відкрийте в браузері `https://node.example.org` — має з'явитися рядок «Nevod node — https://nevod.network», а браузер не повинен лаятися на сертифікат.

Тепер відкрийте `https://node.example.org/nevod-admin`. Браузер запитає логін і пароль: логін — будь-який, пароль — той, що ви вписали в `.env`. Відкриється панель адміністратора. Що в ній зробити насамперед — у розділі [Перше налаштування в панелі адміністратора](../node-panel/).

> П'ять невірних паролів поспіль з однієї адреси закривають вхід у панель для цієї адреси на 15 хвилин. Якщо це сталося — просто зачекайте.

## 10. За бажанням: закрийте панель від інтернету

Якщо ви не хочете, щоб адреса панелі взагалі відкривалася з інтернету, впишіть у `.env` рядок `NEVOD_ADMIN_PUBLIC=false` і застосуйте:

```
docker compose up -d
```

Тоді панель доступна лише через SSH-тунель. На своєму комп'ютері виконайте

```
ssh -L 8766:127.0.0.1:8766 root@node.example.org
```

і, поки це вікно відкрите, відкрийте в браузері `http://localhost:8766/nevod-admin`.

## Якщо щось не так

| Що бачите | У чому зазвичай річ |
|---|---|
| Браузер пише, що сертифікат недійсний, або сайт не відкривається | Домен ще не вказує на сервер (крок 2) або закритий порт 80/443 (кроки 1 і 5). Подивіться журнал Caddy: `docker compose logs caddy`. Коли причину усунуто, Caddy сам повторить спробу. |
| `docker compose up` пише `address already in use` | На сервері вже працює інший вебсервер (часто Apache або nginx від провайдера). Зупиніть його: `systemctl disable --now apache2` або `systemctl disable --now nginx`. |
| Помилка `set NEVOD_ADMIN_PASSWORD in .env` або `set NEVOD_DOMAIN in .env` | Не заповнено цей рядок у `.env` (крок 7). |
| Панель знову й знову питає пароль | Невірний пароль. Подивитися, який записано: `grep PASSWORD .env`. |
| Панель відповідає «Too many failed logins» | Спрацював захист від підбору пароля — зачекайте 15 хвилин. |
| `nevod_node` весь час перезапускається | Журнал вузла покаже причину: `docker compose logs --tail 50 nevod_node`. |

Журнали обох контейнерів цілком: `docker compose logs`. Усі команди `docker compose` виконуються з теки `/opt/nevod/installer/docker`.
