# Обслуживание

Обновление узла, резервные копии, перенос на другой сервер, журналы и обычный уход за сервером. Все команды `docker compose` выполняются на сервере из папки `/opt/nevod/installer/docker`:

```
cd /opt/nevod/installer/docker
```

## Обновление узла

Новые версии узла выходят в [исходном коде на GitHub](https://github.com/avk0978/nevod-messenger) — чтобы узнавать о них, нажмите там **Watch**. Обновление:

```
cd /opt/nevod
git pull
cd installer/docker
docker compose up -d --build
```

Узел перезапустится с новой версией; пользователи переподключатся сами, данные в папке `data/` сохраняются. После обновления загляните в **Диагностику** панели → **Проверить**.

Старые образы после нескольких обновлений занимают место на диске — их можно удалить:

```
docker image prune -f
```

## Резервная копия

Самое ценное на сервере — папка `data/`, а в ней файл `node.json`: это личность узла. Потеряете его — узел придётся создавать заново, с новым идентификатором, и всем пользователям регистрироваться на нём снова. Делайте копию хотя бы раз в неделю и после каждого изменения настроек.

**Сделать копию** (узел остановится на несколько секунд):

```
docker compose stop nevod_node
tar czf ~/nevod-backup-$(date +%F).tar.gz data .env
docker compose start nevod_node
```

**Скачать её к себе.** На своём компьютере:

```
scp root@node.example.org:~/nevod-backup-*.tar.gz .
```

Храните копию не на том же сервере: если с сервером что-то случится, копия пропадёт вместе с ним.

> В копии лежат ключи узла и пароль панели из `.env`. Храните её так же бережно, как пароль: зашифрованный диск, менеджер паролей с вложениями или похожее место.

## Восстановление и перенос на другой сервер

Так же переносят узел на новый сервер. Домен остаётся прежним — меняется только сервер, на который он указывает.

1. На новом сервере выполните шаги 1, 3–6 [установки](../node-install/) (сервер, Docker, файрвол, скачать Nevod) — **без** шагов 7–8.
2. Скопируйте копию на новый сервер и распакуйте её в папку комплекта:

   ```
   scp nevod-backup-ДАТА.tar.gz root@НОВЫЙ-IP:/opt/nevod/installer/docker/
   ```

   и на новом сервере:

   ```
   cd /opt/nevod/installer/docker
   tar xzf nevod-backup-ДАТА.tar.gz
   ```

3. **Остановите узел на старом сервере** (`docker compose down`) — два узла с одной личностью одновременно работать не должны.
4. Смените A-запись домена на IP нового сервера и дождитесь, пока `ping node.example.org` покажет новый адрес.
5. Запустите узел на новом сервере: `docker compose up -d --build`. Caddy сам получит сертификат заново.

Пользователи ничего не делают: приложение подключится к тому же домену и найдёт там тот же узел.

> Сменить **домен** узла так просто нельзя: адрес для связи с другими узлами записан в личность узла при первом запуске. Выбирайте домен, который не придётся менять.

## Журналы

```
docker compose logs --tail 100 nevod_node
docker compose logs -f nevod_node
```

Первая команда показывает последние 100 строк, вторая — журнал в реальном времени (выход — **Ctrl+C**). Журнал Caddy — `docker compose logs caddy`. Последние записи узла видны и в панели: **Диагностика → Логи**.

Журналы ограничены по объёму: 3 файла по 10 МБ на каждый контейнер, старые записи затираются сами. Тексты сообщений в журнал не попадают.

## Перезапуск, остановка, пароль

| Что нужно | Команда |
|---|---|
| Перезапустить узел (например, после смены имени или видимости в панели) | `docker compose restart nevod_node` |
| Остановить всё | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Посмотреть, что работает | `docker compose ps` |

**Сменить главный пароль панели:** впишите новый в строку `NEVOD_ADMIN_PASSWORD` в `.env` (`nano .env`) и выполните `docker compose up -d` — узел перезапустится с новым паролем. Личные учётные записи со страницы «Безопасность» от этого не меняются.

## Уход за сервером

- **Обновления системы** — раз в месяц или чаще:

  ```
  apt update && apt upgrade -y
  reboot
  ```

  После перезагрузки узел, Caddy и coturn (если вы его ставили) запускаются сами.
- **Место на диске** — `df -h /`. Если места мало, удалите старые образы (`docker image prune -f`) и старые резервные копии на сервере.
- **Сертификат HTTPS** Caddy продлевает сам. Делать ничего не нужно, но порт 80 должен оставаться открытым.
- **Узел недоступен?** Проще всего узнать об этом сразу — подключите бесплатный сервис проверки доступности сайтов к адресу `https://node.example.org`: он пришлёт письмо, если узел перестанет отвечать.

## Если узел долго не работал

Сообщения для пользователей, которые не выходили на связь, узел хранит до 72 часов, потом удаляет. Узел, который не выходил на связь 72 часа, другие узлы сети убирают из своих списков — после запуска он вернётся в них сам, по мере обмена списками.
