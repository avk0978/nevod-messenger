# Обслуговування

Оновлення вузла, резервні копії, перенесення на інший сервер, журнали й звичайний догляд за сервером. Усі команди `docker compose` виконуються на сервері з теки `/opt/nevod/installer/docker`:

```
cd /opt/nevod/installer/docker
```

## Оновлення вузла

Нові версії вузла виходять у [вихідному коді на GitHub](https://github.com/avk0978/nevod-messenger) — щоб дізнаватися про них, натисніть там **Watch**. Оновлення:

```
cd /opt/nevod
git pull
cd installer/docker
docker compose up -d --build
```

Вузол перезапуститься з новою версією; користувачі перепідключаться самі, дані в теці `data/` зберігаються. Після оновлення загляньте в **Діагностику** панелі → **Перевірити**.

Старі образи після кількох оновлень займають місце на диску — їх можна видалити:

```
docker image prune -f
```

## Резервна копія

Найцінніше на сервері — тека `data/`, а в ній файл `node.json`: це особа вузла. Втратите його — вузол доведеться створювати заново, з новим ідентифікатором, і всім користувачам реєструватися на ньому знову. Робіть копію хоча б раз на тиждень і після кожної зміни налаштувань.

**Зробити копію** (вузол зупиниться на кілька секунд):

```
docker compose stop nevod_node
tar czf ~/nevod-backup-$(date +%F).tar.gz data .env
docker compose start nevod_node
```

**Завантажити її до себе.** На своєму комп'ютері:

```
scp root@node.example.org:~/nevod-backup-*.tar.gz .
```

Зберігайте копію не на тому самому сервері: якщо із сервером щось станеться, копія зникне разом із ним.

> У копії лежать ключі вузла й пароль панелі з `.env`. Зберігайте її так само дбайливо, як пароль: зашифрований диск, менеджер паролів із вкладеннями або подібне місце.

## Відновлення й перенесення на інший сервер

Так само переносять вузол на новий сервер. Домен залишається тим самим — змінюється лише сервер, на який він вказує.

1. На новому сервері виконайте кроки 1, 3–6 [встановлення](../node-install/) (сервер, Docker, файрвол, завантажити Nevod) — **без** кроків 7–8.
2. Скопіюйте копію на новий сервер і розпакуйте її в теку комплекту:

   ```
   scp nevod-backup-ДАТА.tar.gz root@НОВИЙ-IP:/opt/nevod/installer/docker/
   ```

   і на новому сервері:

   ```
   cd /opt/nevod/installer/docker
   tar xzf nevod-backup-ДАТА.tar.gz
   ```

3. **Зупиніть вузол на старому сервері** (`docker compose down`) — два вузли з однією особою одночасно працювати не повинні.
4. Змініть A-запис домену на IP нового сервера й дочекайтеся, поки `ping node.example.org` покаже нову адресу.
5. Запустіть вузол на новому сервері: `docker compose up -d --build`. Caddy сам отримає сертифікат заново.

Користувачі нічого не роблять: застосунок підключиться до того самого домену й знайде там той самий вузол.

> Змінити **домен** вузла так просто не можна: адресу для зв'язку з іншими вузлами записано в особу вузла під час першого запуску. Обирайте домен, який не доведеться змінювати.

## Журнали

```
docker compose logs --tail 100 nevod_node
docker compose logs -f nevod_node
```

Перша команда показує останні 100 рядків, друга — журнал у реальному часі (вихід — **Ctrl+C**). Журнал Caddy — `docker compose logs caddy`. Останні записи вузла видно й у панелі: **Діагностика → Логи**.

Журнали обмежені за обсягом: 3 файли по 10 МБ на кожен контейнер, старі записи затираються самі. Тексти повідомлень у журнал не потрапляють.

## Перезапуск, зупинка, пароль

| Що потрібно | Команда |
|---|---|
| Перезапустити вузол (наприклад, після зміни назви чи видимості в панелі) | `docker compose restart nevod_node` |
| Зупинити все | `docker compose down` |
| Запустити знову | `docker compose up -d` |
| Подивитися, що працює | `docker compose ps` |

**Змінити головний пароль панелі:** впишіть новий у рядок `NEVOD_ADMIN_PASSWORD` у `.env` (`nano .env`) і виконайте `docker compose up -d` — вузол перезапуститься з новим паролем. Особисті облікові записи зі сторінки «Безпека» від цього не змінюються.

## Догляд за сервером

- **Оновлення системи** — раз на місяць або частіше:

  ```
  apt update && apt upgrade -y
  reboot
  ```

  Після перезавантаження вузол, Caddy і coturn (якщо ви його ставили) запускаються самі.
- **Місце на диску** — `df -h /`. Якщо місця мало, видаліть старі образи (`docker image prune -f`) і старі резервні копії на сервері.
- **Сертифікат HTTPS** Caddy продовжує сам. Робити нічого не потрібно, але порт 80 має залишатися відкритим.
- **Вузол недоступний?** Найпростіше дізнатися про це одразу — підключіть безкоштовний сервіс перевірки доступності сайтів до адреси `https://node.example.org`: він надішле лист, якщо вузол перестане відповідати.

## Якщо вузол довго не працював

Повідомлення для користувачів, які не виходили на зв'язок, вузол зберігає до 72 годин, потім видаляє. Вузол, який не виходив на зв'язок 72 години, інші вузли мережі прибирають зі своїх списків — після запуску він повернеться в них сам, у міру обміну списками.
