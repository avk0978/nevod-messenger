# Звонки через свой узел

Как Nevod соединяет звонки, когда узлу нужен свой ретранслятор звонков (TURN) и как его поставить на тот же сервер. Если вы только начинаете — этот раздел можно пропустить: подключённый к сети узел получает ретранслятор у узлов проекта.

## Как соединяется звонок

Звук и видео идут **напрямую между телефонами**, а узел только помогает им договориться о соединении. Но напрямую получается не всегда: мобильные операторы и многие роутеры прячут телефоны за общими адресами (NAT), и два таких телефона не могут достучаться друг до друга. Тогда звонок идёт через **ретранслятор (TURN)** — сервер, который пересылает пакеты между телефонами.

Звонок зашифрован от телефона до телефона (DTLS-SRTP). Ретранслятор видит только зашифрованные пакеты, адреса телефонов, время и объём звонка — услышать или увидеть разговор он не может.

## Нужен ли вам свой ретранслятор

**Без своего ретранслятора** узел, [подключённый к общей сети](../node-network/), при каждом входе пользователя запрашивает для него доступ к ретранслятору одного из узлов сети, у которых он есть, — выбирается случайный. Звонки работают, и ничего настраивать не нужно. Узел, не подключённый к сети, ретранслятора не получает: звонки между телефонами за NAT у его пользователей могут не соединяться.

**Свой ретранслятор** стоит поставить, если:

- вы хотите, чтобы звонки ваших пользователей не зависели от узлов проекта;
- ваши пользователи далеко от серверов проекта, и звонки через них идут с задержкой;
- у вас много пользователей и много звонков.

Что нужно учесть:

- **трафик.** Через ретранслятор идёт весь звонок: голос — около 100 Кбит/с в каждую сторону, видео — 1–2 Мбит/с. Большинство VPS включают несколько терабайт трафика в месяц — для узла с десятками пользователей этого хватает с запасом;
- **ваш ретранслятор будет помогать и другим узлам сети.** Узел сообщает сети, что у него есть ретранслятор, и узлы без своего будут случайным образом выдавать его своим пользователям. Ниже в настройке есть ограничения, чтобы это не съело весь канал сервера.

## Установка coturn

Ставим coturn — самый распространённый ретранслятор — прямо на сервер узла. Все команды — на сервере.

**1. Установите coturn и придумайте секрет:**

```
apt install -y coturn
openssl rand -hex 32
```

Сохраните результат второй команды — это общий секрет ретранслятора и узла.

**2. Узнайте внешний IP-адрес сервера:**

```
curl -4 ifconfig.me
```

**3. Запишите настройки.** Откройте файл:

```
nano /etc/turnserver.conf
```

удалите всё, что в нём есть, и вставьте, подставив свой IP-адрес и секрет:

```
listening-port=3478
external-ip=IP-АДРЕС-СЕРВЕРА
realm=nevod
use-auth-secret
static-auth-secret=СЕКРЕТ
min-port=49152
max-port=65535
no-tls
no-dtls
fingerprint
no-loopback-peers
no-multicast-peers
denied-peer-ip=0.0.0.0-0.255.255.255
denied-peer-ip=10.0.0.0-10.255.255.255
denied-peer-ip=100.64.0.0-100.127.255.255
denied-peer-ip=127.0.0.0-127.255.255.255
denied-peer-ip=169.254.0.0-169.254.255.255
denied-peer-ip=172.16.0.0-172.31.255.255
denied-peer-ip=192.168.0.0-192.168.255.255
total-quota=200
user-quota=10
max-bps=4000000
```

Сохраните: **Ctrl+O**, **Enter**, **Ctrl+X**.

Строки `denied-peer-ip` запрещают ретранслятору пересылать что-либо на внутренние адреса — в том числе внутрь Docker на этом же сервере. Не удаляйте их. `total-quota`, `user-quota` и `max-bps` ограничивают число одновременных соединений и скорость одного соединения (4 Мбит/с).

**4. Запустите coturn:**

```
systemctl enable --now coturn
systemctl status coturn
```

В ответе должно быть `active (running)`. Если coturn не запускается, откройте `/etc/default/coturn` и раскомментируйте строку `TURNSERVER_ENABLED=1` — в некоторых версиях пакета это нужно.

**5. Откройте порты:**

```
ufw allow 3478/tcp
ufw allow 3478/udp
ufw allow 49152:65535/udp
```

И те же порты — в файрволе провайдера, если он есть.

**6. Передайте секрет узлу.** В папке `/opt/nevod/installer/docker`:

```
nano .env
```

впишите в строку `TURN_SECRET=` тот же секрет и примените:

```
docker compose up -d
```

## Проверка

- **Диагностика → Проверить → Зависимости и конфигурация** — не должно быть предупреждений про TURN.
- Узел выдаёт телефонам адрес ретранслятора `turn:ваш-домен:3478` — домен должен указывать на этот сервер (он и так указывает, если узел работает).
- Позвоните с телефона в мобильной сети на телефон в Wi-Fi. Если звонок соединился и слышно обоих — ретранслятор работает. Журнал coturn: `journalctl -u coturn -n 50`.

> Ретранслятор работает по UDP и TCP на порту 3478 без шифрования канала до ретранслятора (сам звонок зашифрован всегда). В некоторых корпоративных сетях такие порты закрыты — тогда звонки из этих сетей через ретранслятор не пройдут.
