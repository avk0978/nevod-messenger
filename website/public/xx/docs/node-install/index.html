Установка шаг за шагом

Как поставить узел Nevod на арендованный сервер с нуля: от покупки сервера до первого входа в панель администратора. Пример — сервер с Ubuntu 26.04 и домен node.example.org; вместо него везде подставляйте свой.

Все команды ниже вводятся в терминале сервера, их можно копировать целиком. Что такое узел и что он хранит — в разделе Как устроен узел.

1. Арендуйте сервер

Подойдёт любой VPS у любого провайдера: 1 процессор, 1 ГБ памяти, 10 ГБ диска, система Ubuntu 24.04 или 26.04. При заказе провайдер выдаст IP-адрес сервера и пароль пользователя root (или попросит загрузить SSH-ключ).

Если у провайдера есть свой сетевой файрвол в панели управления (например, Firewalls у Hetzner, Security groups у других), откройте в нём входящие порты 22, 80, 443 и 8765 (TCP).

2. Направьте домен на сервер

Для узла нужен свой домен или поддомен, например node.example.org. Без него не обойтись по двум причинам:

  • Телефоны подключаются к узлу по адресу https://домен/nevod-ws. Сертификат HTTPS, которому iPhone доверяет без всяких настроек, Caddy получает от Let's Encrypt на доменное имя.
  • Адрес узла хранится у всех: в телефонах пользователей, в их контактных карточках, у других узлов сети. Если вы переедете на другой сервер или провайдер сменит IP-адрес, достаточно поправить одну DNS-запись — пользователи ничего не заметят. С голым IP-адресом после переезда связь пропала бы у всех, и приглашения пришлось бы рассылать заново.

Если своего домена ещё нет, его можно купить у любого регистратора (Cloudflare, Namecheap, Porkbun, Gandi и другие) — обычно это несколько долларов или евро в год. Для узла достаточно одного поддомена, а сам домен можно использовать и для чего-то ещё.

В панели управления вашим доменом создайте A-запись: имя — например node (получится node.example.org), значение — IP-адрес сервера.

Подождите несколько минут и проверьте с любого компьютера:

ping node.example.org

В ответе должен быть IP-адрес вашего сервера. Пока этого нет, дальше идти бессмысленно: сертификат HTTPS выдаётся только домену, который уже указывает на сервер.

Если домен обслуживает Cloudflare, отключите для этой записи проксирование (серое облако, «DNS only»). Иначе телефоны и другие узлы будут подключаться к Cloudflare, а не к вашему серверу.

3. Подключитесь к серверу

На своём компьютере откройте терминал (на Windows — PowerShell, на Mac — «Терминал») и введите:

ssh root@node.example.org

При первом подключении ответьте yes и введите пароль от провайдера.

4. Установите Docker и git

apt update && apt upgrade -y
apt install -y git
curl -fsSL https://get.docker.com | sh

Последняя команда — официальный установщик Docker. Проверьте, что всё на месте:

docker compose version

Должна появиться строка вида Docker Compose version v….

Если после обновления на экране или при следующем входе появилась надпись *** System restart required ***, перезагрузите сервер командой reboot, через минуту подключитесь снова (шаг 3) и продолжайте.

5. Включите файрвол

ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8765/tcp
ufw enable

На вопрос ответьте y. Порты 80 и 443 нужны для HTTPS (телефоны и панель), 8765 — для связи с другими узлами.

Docker открывает порты своих контейнеров сам, в обход ufw. Поэтому в нашем комплекте панель администратора (порт 8766) опубликована только для самого сервера — не меняйте это в docker-compose.yml.

6. Скачайте Nevod

Все команды дальше вводятся на сервере: слева в строке ввода должно быть root@…. Если там PS C:\…> или имя вашего компьютера, соединение с сервером закрылось — подключитесь снова (шаг 3).

git clone https://github.com/avk0978/nevod-messenger.git /opt/nevod
cd /opt/nevod/installer/docker

7. Заполните настройки

Создайте файл настроек из образца:

cp .env.example .env

Придумайте пароль для панели администратора. Удобнее всего сгенерировать длинный случайный:

openssl rand -base64 24

Скопируйте результат и сохраните его в надёжном месте — например, в менеджере паролей (Bitwarden, KeePass, «Пароли» на iPhone и Mac). Теперь откройте файл настроек:

nano .env

Измените две строки:

NEVOD_DOMAIN=node.example.org
NEVOD_ADMIN_PASSWORD=сюда-сгенерированный-пароль

Остальное оставьте как есть. Сохраните файл: Ctrl+O, затем Enter, выход — Ctrl+X.

НастройкаЧто значит
NEVOD_DOMAINДомен узла. Телефоны подключаются к https://домен/nevod-ws, другие узлы — к домен:8765.
NEVOD_ADMIN_PASSWORDПароль панели администратора. Без него узел не запустится.
NEVOD_ADMIN_PUBLICtrue — панель открывается в браузере по адресу https://домен/nevod-admin; false — панель закрыта для интернета (см. шаг 10).
TURN_SECRETТолько если вы ставите свой ретранслятор звонков, см. Звонки через свой узел. Обычно пусто.

8. Запустите узел

docker compose up -d --build

Первый запуск занимает несколько минут: Docker собирает образ узла и скачивает Caddy. Когда команда закончится, проверьте:

docker compose ps

Оба контейнера — nevod_node и nevod_caddy — должны быть в состоянии Up (или running).

9. Проверьте, что всё работает

Откройте в браузере https://node.example.org — должна появиться строка «Nevod node — https://nevod.network», а браузер не должен ругаться на сертификат.

Теперь откройте https://node.example.org/nevod-admin. Браузер спросит логин и пароль: логин — любой, пароль — тот, что вы вписали в .env. Откроется панель администратора. Что в ней сделать в первую очередь — в разделе Первая настройка в панели администратора.

Пять неверных паролей подряд с одного адреса закрывают вход в панель для этого адреса на 15 минут. Если это случилось — просто подождите.

10. По желанию: закройте панель от интернета

Если вы не хотите, чтобы адрес панели вообще открывался из интернета, замените в .env строку NEVOD_ADMIN_PUBLIC=true на NEVOD_ADMIN_PUBLIC=false и примените:

docker compose up -d

Тогда панель доступна только через SSH-туннель. На своём компьютере выполните

ssh -L 8766:127.0.0.1:8766 root@node.example.org

и, пока это окно открыто, откройте в браузере http://localhost:8766/nevod-admin.

Если на вашем компьютере порт 8766 уже занят (например, там работает другой узел Nevod), возьмите другой: ssh -L 18766:127.0.0.1:8766 root@node.example.org и http://localhost:18766/nevod-admin. Первое число — порт на вашем компьютере, второе — порт панели на сервере, его не меняйте.

Если что-то не так

Что видитеВ чём обычно дело
Браузер пишет, что сертификат недействителен, или сайт не открываетсяДомен ещё не указывает на сервер (шаг 2) или закрыт порт 80/443 (шаги 1 и 5). Посмотрите журнал Caddy: docker compose logs caddy. Когда причина устранена, Caddy сам повторит попытку.
docker compose up пишет address already in useНа сервере уже работает другой веб-сервер (часто Apache или nginx от провайдера). Остановите его: systemctl disable --now apache2 или systemctl disable --now nginx.
Ошибка set NEVOD_ADMIN_PASSWORD in .env или set NEVOD_DOMAIN in .envНе заполнена эта строка в .env (шаг 7).
Ошиблись в домене в .env (сертификат не выдаётся, в журнале Caddy — NXDOMAIN)Остановите узел: docker compose down, исправьте NEVOD_DOMAIN в .env, удалите папку данных: rm -rf data, и запустите снова: docker compose up -d. Удалять data можно, только пока на узле никто не зарегистрирован, — иначе узел останется со старым адресом, а исправлять его придётся вручную.
Панель снова и снова спрашивает парольНеверный пароль. Посмотреть, какой записан: grep PASSWORD .env.
Панель отвечает «Too many failed logins»Сработала защита от подбора пароля — подождите 15 минут.
nevod_node всё время перезапускаетсяЖурнал узла покажет причину: docker compose logs --tail 50 nevod_node.

Журналы обоих контейнеров целиком: docker compose logs. Все команды docker compose выполняются из папки /opt/nevod/installer/docker.
